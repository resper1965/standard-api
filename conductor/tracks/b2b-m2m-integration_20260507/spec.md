# Specification: B2B M2M Integration & SaaS Governance

**Track ID:** b2b-m2m-integration_20260507
**Type:** Feature
**Created:** 2026-05-07
**Status:** Completed (Documented Post-Factum)

## Summary

Implement a Machine-to-Machine B2B integration endpoint for external systems (e.g., Privacy Apps) to stream raw text/ROPA into the Aegis/Standard Agentic Engine. Concurrently, formalize and document the SaaS Core API allowing Superadmins and Tenant Admins to handle Subscriptions, Organizations, and secure M2M API Keys with strict RBAC segregation.

## Context

The system transitions from an interactively-driven portal to an API-First SaaS Hub. Third-party partners rely on Standard as the core intelligence layer. To fulfill this, Standard requires a robust external facing `/analyze-text` endpoint backed by async AI Queues, paired with strict SaaS administrative capabilities to govern who can call this endpoint and how billing/keys are segregated.

## User Story

As a **Tenant Admin**, I want to securely connect my native systems to the Standard API using M2M keys so that my software can autonomously flag SCF vulnerabilities derived from unstructured text.

As a **Global Superadmin**, I want to enforce strict SaaS provisioning rules so that organizations remain perfectly isolated and system API Keys cannot be escalated or used for administrative actions.

- [x] Isolate M2M roles gracefully from RBAC, forbidding keys from fetching/generating more keys or modifying the Organization.

## Dependencies

- **Cloudflare D1/Postgres Driver:** Proper Tenant metadata and ApiKey schemas must exist.
- **Agent Runtime:** Requires functional integration with `AI Gateway` mapping.
- **RBAC Middleware:** Requires role verifications mapping to authentication states.

## Out of Scope

- OIDC or Frontend interactive interfaces involving these M2M API endpoints (they belong strictly to external servers).
- User/Admin UI creation (this track ensures the *API endpoints* exist for UI fetching later).
